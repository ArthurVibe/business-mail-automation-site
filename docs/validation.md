# Отчёт о переносе v4.8

Дата: 31 октября 2026. Ветка: `feature/task-01-prototype`. Эталон предоставлен заказчиком как вложение; SHA-256: `4247f1a4936df0e1ee7c9820f04bc2e1de301272f823346988ef96efd5f3445d`.

## Что сделано и архитектура

Монолит перенесён на Vite и Vanilla JavaScript ES modules: девять HTML-компонентов, отдельные стили, пять функциональных JS-модулей и точка инициализации. Локальный Vite-плагин объединяет компоненты до отдачи HTML. Три уникальных изображения извлечены в `public/assets/images`; их размеры и SHA-256 совпали с исходными данными. Повторяющийся PNG использует один файл. Prettier и зафиксированные dev-зависимости включены в lockfile; runtime-зависимостей нет.

Сохранены весь продуктовый текст (проверено сравнением статического HTML с нормализацией пробельных символов), фоновые сферы, палитра, системный стек шрифтов, композиция, тарифы START/BUSINESS/CUSTOM, обе демонстрации, оба сценарных консультанта, Live Proposal и два TXT-экспорта. Формулы и исходные значения вынесены без изменения в `calculateEconomics`; тарифная рекомендация Workspace, как в оригинале, не переключает выбранную карточку автоматически. Сброс Workspace сохраняет калькулятор.

## Соответствие прототипу и технические исправления

Контрольные скриншоты оригинала получены **до переноса** на всех пяти ширинах. Для экономики дополнительно снят эталон с принудительным `.on`: оригинальный CSS скрывал эту секцию. Это диагностическая правка только при съёмке оригинала, а не замена эталона.

Для сравнения использованы одинаковые Chromium, высота 900 px и scale factor 1. Секции сравнивались по кропам полной страницы, чтобы липкая навигация в промежуточной позиции прокрутки не создавала ложные различия. Hero, демонстрация, экономика и Workspace совпали пиксель в пиксель на всех пяти ширинах. В консультанте небольшое различие растеризации: 0,31% пикселей при 768 px и 0,038% при 1440 px; при 375/390/1024 px совпадение точное. Размеры секций сохранены; при 1440 px возможна разница округления в 1 px. Исходные переносы строк входных данных workflow защищены `prettier-ignore`, поскольку `white-space: pre-line` делает их частью дизайна.

Осознанные технические исправления:

1. Удалено устаревшее ID-правило, скрывавшее экономику. Все три секции постоянно находятся в потоке документа согласно прямому требованию ТЗ.
2. Отступ прокрутки учитывает измеренную высоту sticky-навигации, включая мобильные переносы подписей.
3. Кнопка «Показать обработку» больше не делает только повторный скролл: запускает существующий сценарий с исходными 850 мс на шаг и выводит его исходные статусы/результат в уже существующее пояснение. Скрытый старый Hero-виджет не раскрывается, сценарии и действующий RFQ workflow не заменены.
4. Добавлена защита нечислового ввода и переполнения калькулятора. На обычных и исходных граничных значениях порядок вычислений и форматирование сохранены.
5. Поля калькулятора связаны с существующими подписями. Модальный Workspace удерживает клавиатурный фокус, корректно открывается после мобильной вкладки Live Proposal и закрывается перед переходом к калькулятору.
6. Неиспользуемый `toggleCalc`, обращавшийся к отсутствующей кнопке, не перенесён; новые элементы интерфейса для него не создавались.

Локальные доказательства этой сессии находятся вне Git: `/workspace/validation/baseline/`, `/workspace/validation/after/`, `/workspace/validation/comparable/`, `playwright-report/`. Это артефакты текущей машины, не обещание их наличия в новом checkout. Обнаруженное при сравнении схлопывание переносов workflow исправлено и покрыто точным браузерным утверждением. Итоговые метрики сохранены в [visual-comparison.json](visual-comparison.json).

## Безопасность

Проверены исходный HTML/CSS/JS, комментарии, URL, встроенные изображения и итоговые модули/конфигурация. Ключей API, паролей, webhook, закрытых endpoint, реальных клиентских данных и чувствительных рабочих заметок не обнаружено. Пользовательский ввод вставляется через `textContent`, не через HTML. Сайт не делает внешних API-запросов и не сохраняет переписку в браузерном хранилище. В изображениях сохранены публичные C2PA-метаданные, включая сертификаты; их URL не являются запросами приложения. В репозиторий не включены исходный монолит, ТЗ-вложение, секреты, `node_modules`, `dist` и трассировки браузеров. Dependency audit после выбора исправленной Vite 7.3.7 — 0 уязвимостей.

## Среда и оставшиеся ограничения

В черновик облачной среды сохранены `install_script`, `start_skill` и добавления сетевых доменов `api.github.com`, `cdn.playwright.dev`, `playwright.download.prss.microsoft.com` с сохранением preset package_managers. Установка, запуск dev-сервера и production preview проверены в текущей машине. Сохранение черновика не применяет сетевую политику и не публикует среду.

Для загрузки Firefox/WebKit и создания PR нужен разрешённый доступ к указанным адресам. Текущий прокси отклоняет CONNECT к GitHub API с HTTP 403; `gh api`/`gh pr list` также получают Forbidden. Git-доступ к выбранному репозиторию работает. Новый токен не запрашивался: отсутствие токена не установлено причиной, подтверждён именно сетевой отказ.

Полная кроссбраузерная приёмка и создание Pull Request остаются незавершёнными до снятия сетевого ограничения. В настройках среды нужно проверить и сохранить изменения сети; для повторного использования подготовленного снимка затем опубликовать **облачную среду**. Это не публикация сайта. После применения доступа необходимо повторить установку движков, браузерные тесты и создание PR. Восстановление среды в новой задаче ещё не проверялось.

Сайт не опубликован, DNS и домен не настроены, реальные внешние API не подключены. Изменения не объединены с `main`.
